# Object-avoidance-robot
In this repository, I discuss a project i was apart of last semester where my team built a robot from a MakeBlock kit. This includes the description, simulations and code.
Last semester apart of our module Robotics and control PBL. Me and my teammates built a MakeBlock robot and implemented an Object avoidance and line-following algorithm. We only had two requirements: 1. Use the MakeBlock kit with the MegaPi. 2. Implement a feedback control loop to it. So we had a lot of room for our imagination. 

After building the robot we added the components that we planned on using. First were the motor drivers, these simply had one job when the microcontroller told them to move it moved. Next we used an ultrasonic sensors, the sensors works by sending out waves of infrared lights. If the infrared light doesn't shine back into the sensor it knows that there is no objects ahead, else it can get the distance the object by checking how long it took the light to shine back. This allowed us to have our robot stop when it sensed an object is too close. Our last component was the line sensor, This component works by measuring the contrast of the ground. So we built a track on a light material and created the line with black electrical tape. When the sensor noticed that it wasn't on the line or not fully it would adjust the robot until the sensor was back on the line. Although we did run into problems if the robot ran into a very sharp or "hairpin" turn would either take a long time or cause the robot to do a full 180 rotation. All of these components were connected to the same MegaPi so we were able to code all the components together.

When running simulations for our control loop we decided to use the same software we learned in our labs for our systems and control module. MATLAB and Simulink, as we used these during these modules we found that they were accurate and industry standard so we went with them. We were able to gain a first order transfer function for our system: 1/(0.05s + 1). We ran simulations for the motor drivers with constant rpm and a Simulink model of the motor. This greatly helped us in development for our system. Although we did run into problems with the motor drivers had to me manually configured to detect pulses.
